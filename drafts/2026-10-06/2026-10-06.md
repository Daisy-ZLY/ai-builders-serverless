**原文：**
> DHH is fundamentally right about Rust. For context, Vercel has been undergoing a Rust-ification (carcinization, technically 🦀) for a while. One of the first projects we migrated was Turborepo, from Go to Rust. The migration completed, but the RoI was actually quite controversial internally. While Rust was in our eyes better for low-level OS access, something crucial for a build system like Turbo, the human migration costs were very substantive. Go is very fast. It's beautifully designed. It's easy to iterate on. We were very conflicted about the migration, because it was *humans* writing the code, *even if we knew Rust was a better choice*. The calculus has now changed. What's "best for humans" is no longer necessarily "best for business". FWIW, it's also quite unlikely that Rust is the end-all-be-all toolchain. I'm quite certain there's greener pasture ahead, because Rust itself was designed before the 'supersonic tsunami' of agents hit.
> 
> Working on a new little project. The README is fully written by hand, because it's for human consumption. The documentation internals are AI English, because they're for agents. This little rule of thumb can make the world better. Blogs, tweets, READMEs: human communication. It's not even about "em dashes" or lack thereof. It's that it's the story-telling moment where you want to connect with other humans through their words.
> 
> It's hard to fathom [Vercel] getting even faster, but it's now… much faster 😂 As models speed up (as with Astra ultrafast), harness overhead matters more and more. Next release will feature even better performance for session storage and retrieval, and a big unlock for cloud durability in libfx.

**中文解读：**
Guillermo Rauch 这三条推文串起来看，核心是在讲 AI agent 时代对技术栈和工程实践的重塑。第一，他以 Turborepo 从 Go 迁移到 Rust 为例，坦承虽然 Rust 在底层系统访问上更优，但人力迁移成本极高，内部对 ROI 争议很大——不过现在因为 AI agent 能大幅降低迁移成本，'对人类最优'和'对业务最优'的等式被打破了。第二，他提出一个很有意思的实践准则：README、博客、推文这些给人看的内容应该手写，而给 agent 看的内部文档则用 AI 生成。第三，他透露 Vercel 性能进一步提升，并强调当模型推理速度越来越快时，harness 层的开销变得愈发关键。

**大白话：**
Vercel 老板说：以前从 Go 换到 Rust 太费人力，不划算；但现在有 AI 帮忙写代码，换语言这件事突然变得划算了。另外他觉得，给人看的东西要亲手写，给 AI 看的东西让 AI 写就行。

**辩证视角：**
🟢 如果他说得对：如果 AI agent 真能大幅降低语言迁移和重构的人力成本，那么'技术选型'的逻辑将被彻底改写——团队可以更激进地选择理论最优方案，而不必迁就'人类写起来舒服'的语言。这会加速整个基础设施层的性能竞赛，也可能催生专为 agent 协作设计的新编程语言或工具链。同时，'人类文档 vs AI 文档'的分野可能成为行业标准实践，让开发者把精力集中在真正需要人类叙事能力的地方。
🔴 但另一面是：但另一面是，Rust 的学习曲线和编译时间问题并不会因为 AI 写代码就消失——AI 生成的 Rust 代码同样需要人类 review 和维护，长期维护成本未必降低。此外，'AI 文档给 agent 看'这个假设依赖于 agent 能稳定解析非结构化文档，而当前 LLM 对文档格式的鲁棒性仍不稳定。历史上，'AI 会解决一切工程问题'的预期多次被现实打脸，比如早期低代码平台也曾承诺消灭手写代码。
🎯 判断线索：关注 Vercel 后续是否真的用 AI 完成了更多语言迁移（比如其他 Go 项目转 Rust），以及 libfx 的 cloud durability 功能落地后社区反馈如何。另外可以观察是否有其他公司跟进'README 手写、内部文档 AI 写'的实践。

### Matt Turck — AI 模型是「种」出来的，不是「造」出来的——可解释性为何如此紧迫 #话题/可解释性 #话题/AI安全 #话题/大模型 #话题/AI治理

**原文：**
> Still one aspect of AI that's most poorly understood outside AI circles... "models are grown, not built" and we don't *really* know how they work. Hence the urgent need for better interpretability -- @eric_ho @GoodfireAI

**中文解读：**
Matt Turck 点出了一个 AI 圈外普遍被忽视的关键事实：大模型不是像造汽车那样按图纸组装出来的，而是像种庄稼一样「长」出来的——我们给它数据、算力和训练目标，它自己涌现出能力，但内部到底怎么运作，连开发者也无法完全解释。正因如此，interpretability（可解释性）才成为当务之急，Eric Ho 和 GoodfireAI 这类团队正是在做「给模型做 CT 扫描」的工作。这背后是 AI 安全与可控性的核心命题：你无法管理一个你无法理解的东西。

**大白话：**
大模型不是工程师一行行写出来的，而是像养孩子一样「养」大的——它脑子里到底在想什么，连造它的人都不完全清楚。所以现在有一批人专门研究怎么「读懂」AI 的大脑，这事非常急。
