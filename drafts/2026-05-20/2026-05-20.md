> 
> 1. Think about the model and harness together

> 
> 5. Anthropic's writing culture helps Claude build context
> 
> Every written word at Anthropic becomes context Claude can pull later. From Alex: "Get things written down, make them accessible to Claude, because that's just more context that it has."

**原文：**
> Implement <SPEC>. As you work maintain a running implementation-notes.html file that captures anything I should know about how the implementation diverges from or interprets the spec, including:
> 
> - Design decisions: choices you made where the spec was ambiguous
> - Deviations: places where you intentionally departed from the spec, and why
> - Tradeoffs: alternatives you considered and why you picked what you did
> - Open questions: anything you'd want me to confirm or revise
> 
> as much as you spec there are always still ambiguities and unknown unknowns that come up and this gives the model a good out to make decisions but keep you in the loop

**中文解读：**
Thariq 提出了一种让 AI 编码 agent 更可控的方法：要求它在实现规范时，同步生成一个 implementation-notes.html 文件，记录设计决策、偏离规范的原因、权衡考量以及待确认问题。这相当于给 AI 一个“思考日志”，让开发者能追踪其推理过程，避免黑箱操作。核心洞察是：即使规范再详细，总有歧义和未知，这个文件给了 AI 一个“出口”来做出合理决策，同时保持人类的知情权。

**大白话：**
让 AI 写代码时，顺便写个“工作笔记”，把拿不准的地方、为什么这么选都记下来，这样你就能知道它脑子里在想啥，出了岔子也好追责。

**辩证视角：**
🟢 如果他说得对：如果推广开来，这将成为 AI 辅助编程的标配实践，大幅提升 agent 的可解释性和信任度。开发者能更放心地授权 AI 自主决策，因为所有关键选择都有据可查，类似软件工程中的设计文档自动化。
🔴 但另一面是：要求 AI 同时维护额外文件会增加 token 消耗和响应时间，对于简单任务可能过度工程化。而且 AI 生成的“思考日志”可能不够诚实或准确，需要人工验证，反而增加负担。
🎯 判断线索：观察主流 AI 编码工具（如 GitHub Copilot、Cursor）是否引入类似“决策日志”功能，以及开发者社区对这种元文档的实际采纳率。

### Aaron Levie — Agent策略的核心挑战是数据策略 #话题/AIAgent #话题/数据策略 #话题/企业AI #话题/上下文管理

**原文：**
> This is true of all agents, not just coding agents. Probably the biggest challenge that most companies run into in their agent strategy is getting agents the right constrained context to work with for a task. Too much information or conflicting sources, and the agent can easily draw from the data and produce the wrong result. Conflicting sources of truth for documents, data sources that haven’t been kept up to date, knowledge management systems that rely on tribal knowledge to navigate, and so on. On the other end, of course, too little information and the upside is highly limited of agents in the first place. Thus, a lot of challenges with AI strategies are actually data strategy challenges in disguise. This is why there’s such a significant premium on getting structured and unstructured data environments setup properly so agents can work with information effectively. Critical for any large enterprise adopting agents, and also a clear benefit in some cases to startups that can be designed this way from scratch.

**中文解读：**
Aaron Levie 指出，所有 agent（不仅仅是 coding agent）面临的最大挑战是：如何为任务提供恰到好处的上下文。信息过多或来源冲突会导致 agent 产生错误结果；信息过少则限制 agent 的价值。因此，很多 AI 策略问题本质上是数据策略问题。企业需要精心设计结构化和非结构化数据环境，让 agent 能有效利用信息。这对大型企业至关重要，而初创公司从零开始构建反而有优势。

**大白话：**
AI agent 好不好用，关键看数据喂得对不对。给太多乱数据它会犯错，给太少它又没用。所以搞 AI 之前，得先把数据整理好。

**辩证视角：**
🟢 如果他说得对：如果企业能优先解决数据治理问题，agent 的准确性和效率将大幅提升，AI 落地的成功率会显著增加。这可能导致企业更愿意投资数据基础设施，并催生一批专注于数据清洗和上下文管理的工具。
🔴 但另一面是：但数据策略并非万能。agent 的推理能力、模型本身的局限性以及任务复杂度同样关键。即使数据完美，agent 仍可能因缺乏常识或逻辑错误而失败。此外，数据治理成本高昂，中小企业可能难以负担。
🎯 判断线索：观察企业 agent 项目的失败原因：是否多数归因于数据冲突、过时或缺失？如果是，则 Levie 的观点成立。另外，关注数据治理工具（如向量数据库、知识图谱）的采用率是否随 agent 部署而上升。
